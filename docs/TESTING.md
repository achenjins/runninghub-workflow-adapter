# 1.3.2 部署与验证

当前代码版本 `1.3.2`，包含工具拆分、最近图片缓存、自然语言权限、同一工作流多任务排队和独立 Bot 每日额度更新。面向 MaiBot 1.2.x／SDK 2.x 和 NapCat 适配器。下文记录的自动测试使用实际安装的 SDK、模拟宿主与平台响应、临时配置和任务日志；未连接部署服务器或执行付费生成。以下保留部署与人工验收说明。

## 部署

1. 备份服务器插件目录内的 `config.toml` 和运行目录中的 `task_journal.json`。保留旧任务日志，新版能够读取 1.1 的远端任务编号和状态。
2. 停用插件，将测试包中的 `runninghub-workflow-adapter/` 代码覆盖到原插件目录。测试包不包含 `config.toml`、API Key、运行数据或 `.git`。
3. 保留你的工作流 ID、节点映射和对应区域 API Key。新增配置缺失时自动使用默认值；参考根目录 `config.example.toml` 和 `examples/natural-language.toml` 配置用途与素材角色。示例中的 ID 必须替换。
4. 如需聊天中识别并写入工作流，先填写 `access.admin_users`。默认 `manage_workflows_admin_only = true`。
5. 重载插件，核对 `rh_workflows`、`rh_media`、`rh_inspect_media`、`run_workflow`、`rh_task` 已启用，旧 `rh_context` 不再注册，并允许 `message.get_recent`、`message.get_by_id` 能力。
6. 在「聊天生成 → 视觉模型」下拉选择模型，选项依次为 `replyer`、`planner`、`utils`、`vlm`，默认是 `vlm`，旧配置的空值也使用此默认项。图像摘要缓存按模型和内容区分。视频／音频支持上传和角色绑定，目前不自动分析帧或转写音轨。
7. 头像素材：`natural_language.avatar_candidates`（默认开启）把当前用户 QQ 头像（群聊还有群头像）注入素材候选，media_id 形如 `avatar:群内QQ`/`avatar-group:群号`，支持「画我/用我头像」；目标只取宿主可信身份，经 NapCat `get_avatar` 解析，失败自动回退 qlogo 公开直链，响应做图片魔数与大小校验。本地文件直读收紧为白名单（系统临时目录 + 插件缓存目录），UNC/file:// 与符号链接逃逸一律拒绝。
8. 命令必须使用宿主明确提供的调用人；工具缺少请求人时使用 Bot 当前会话作用域，不再借用最近发言人身份，也没有发言人过期时限。只有宿主明确提供请求人时，才可访问该人的个人缓存、头像和管理权限。工具独立使用「聊天生成 → Bot 工作流每日限制」（`natural_language.max_workflows_per_day`，0 不限制），所有用户、会话和工作流共用；群白名单继续生效。命令和插件 API 保留用户白名单、群白名单与个人小时额度。验证两个方向的额度互不占用、多人聊天正常调用、当日上限为 0、并发预约、跨日重置、重启恢复与旧日志迁移；确认最近发言人为管理员也不能让身份未知的工具获得其权限或个人素材，且 Bot 任务不能跨会话管理。排队后的群权限仍会复核。

### 升级时提示缺少 `plugin.config_version`

Runner 会在调用插件的配置解析和 `on_load` 前检查版本。插件创建时会先备份旧文件到同目录的 `config.toml.pre-version-时间戳.bak`，仅补齐缺失或为空的版本号；已有非空版本号及其他配置值保留；`1.2.0` 配置可以继续使用，无需手动改版本号。更新代码后需要重载插件（必要时重启 MaiBot），仅保存配置不会替换仍在运行的旧代码。备份含原配置，请按配置文件同样保管，不要提交到仓库。

若仍在使用旧代码，可先在服务器插件 `config.toml` 已有的 `[plugin]` 表内补上 `config_version = "1.3.2"`，再重载。若没有 `[plugin]` 表，在文件开头新增该表和版本行；不要重复创建同名表，也不要把版本行写到 `[server]` 或工作流表下。

## 建议验证顺序

每条生成测试都可能消耗 RunningHub 余额，先使用自己的低成本工作流。所有场景均应核对 RunningHub 后台实际任务数，以及聊天中的结果和任务编号。

| 场景 | 操作 | 预期 |
|---|---|---|
| 原有命令 | `/rh运行 文生图 一只猫` | 开始时一句短提示，完成后发送结果；缺项时仍有收集提示 |
| 自然语言文生图 | 「帮我画一只窗边的猫」 | 可直接运行；唯一匹配工作流无需额外选流模型调用 |
| 当前参考图 | 发图并说「换成水彩，保留人物和构图」 | 当前图绑定正确，原约束保留 |
| 引用参考图 | 引用同会话旧图说「把这张图背景换成蓝色」 | 使用被引用图片；能重新读取原图或刷新文件信息 |
| 近期素材隔离 | A、B 各发一张图，A 要求修改自己的上一张 | 自动候选只含 A 的近期素材；B 的图仅在 A 明确引用时可用 |
| 多图用途明确 | 「第一张作主体，第二张作风格」 | 两个 input_key 绑定对应 media_id |
| 多图用途不明确 | 仅发两张图要求使用多图工作流 | 询问用途，不按到达顺序猜测角色 |
| 缺少输入 | 只提供主体图，工作流还需要风格图 | 只问缺少的风格图；补充后保留原提示词 |
| 修改参数 | 「宽度 1024，其他不变」 | 只覆盖 width，其余沿用配置；超范围不提交 |
| 继续修改 | 「上次生成的那张，把背景换蓝色，眼睛不变」 | 通过任务 ID 保留原约束；结果素材可作为新参考图选择 |
| 图生视频 | 指定首帧、尾帧及动作 | 图片角色与视频参数对应正确；发送视频或可用下载链接 |
| 输入时取消 | 上传过程中发送 `/rh中断` | 命令不会被当作提示词；取消后不再提交生成 |
| 额度竞争 | 限额设为 1，连续发两个不同需求 | 最多接受一次，排队也占用额度 |
| 热更新并发数 | 任务运行时把并发上限从 2 改成 1 | 现有任务继续；新任务等名额，不产生额外并发 |
| 网络中断 | 远端运行时暂时断开服务器网络，再恢复 | 本地保留远端编号，恢复查询；不再提交第二个任务 |
| 插件重启 | 远端任务未完成时重载 | 查询原远端编号并发送结果；排队任务可恢复 |
| 部分发送失败 | 多输出中一项未发送后 `/rh补发 任务ID` | 只补发未确认发送的项，不重新生成 |
| 同轮重复调用 | 同一消息上重复相同提示词、参数和参考图，仅修改开始提示或刷新图片缓存 | 返回已有任务，不多扣一次生成费用、不重发开始提示 |
| 同轮多任务 | 同一消息上多次调用同一工作流，使用不同提示词、参数或参考图 | 分别创建任务并排队，分别计入小时额度；不能返回其他任务的 ID |
| 取消与完成同时发生 | 已提交任务即将完成时取消 | 后到的取消响应不覆盖已经保存的成功结果 |
| 取消被拒 | 远端明确拒绝取消 | 保留远端编号与名额并继续查询；远端随后完成时照常发送结果 |
| 缺少宿主群号 | 工具 kwargs 无群号，但触发消息带群信息 | 使用触发消息群号检查权限，并向原群发送成品 |
| 结果通知 | 观察一次成功或失败的后台处理 | 插件不同时发固定结束文字和唤醒模型；同一通知事件不重复触发 |

## 状态与恢复

自然语言任务排队后返回 `stop_after_execution=true`，模型应结束本轮，不另发排队确认、不调用 `wait` 或自动轮询 `rh_task`。`start_message` 是本次工具调用携带的一句开始提示，由工作线程获得名额后代发，不额外调用模型。未填写时使用简短默认语句。`rh_task` 留给用户主动查询、取消和补发。

后台结果统一通过 `maisaka.proactive.trigger` 写入模型上下文并唤醒模型，不再重复调用 `context.append` 或先发固定结束文字。开始提示和结果通知都先写入任务日志中的去重标记；明确不支持主动通知时才改发简短文字，响应不确定时不自动补发。这个策略优先避免重复：进程恰在标记落盘后、通知发出前退出，可能漏掉文字通知，任务状态和已生成结果仍可查询；它不保证跨系统“恰好一次”送达。

`run_workflow.output_type` 填用户要求的成品类型，`use_reference=true` 表示需要参考素材或编辑。它们用于筛选工作流，避免只有一个候选时忽略输入需求。工作流已有固定参考素材且用户要求替换时，仍须明确绑定本次素材，不能静默沿用固定素材。单条消息可以对同一工作流提交多个不同生成任务，提示词、有效参数或参考图不同即分别排队，并各占一次小时额度；相同生成内容的重复调用复用原任务，单独修改开始提示不创建新任务。

工作流中的「扩写提示词」开启后，会使用已选择的视觉模型生成参考图摘要；模型均在配置页下拉选择，不需手填。摘要失败会记录原因，继续按原始参考图和用户要求生成。取图或上传失败会在任务记录中保存阶段及具体错误。

## 中文配置页面

配置页使用短中文标题与说明。模型下拉选项仅有 `replyer`、`planner`、`utils`、`vlm`，按此顺序显示，其他工作流选项仍使用中文。节点识别、提示词扩写和工作流选择模型默认 `utils`，视觉模型默认 `vlm`。输入节点的「必须提供内容」默认关闭，已有明确保存的开关值不会被强制改写；验证必填拦截时需主动开启。

新增 `rh_generic_lib/configuration.py` 集中维护配置。更新部署时请一并复制该文件。配置键名保持兼容；模型值保存为 `replyer`、`planner`、`utils`、`vlm` 原始名称，之前的「回复模型」「规划模型」「通用模型」「视觉模型」兼容读入，保存时自动转换为对应原始名称。工作流等其他中文选项在整份配置的读取与保存边界转换，旧英文值仍可读取，保存后转为中文；工作流子模型导出的任务快照仍保留平台原始标识，旧任务无需迁移。

### 最近图片记录

部署时需要一起更新 `rh_generic_lib/image_memory.py`。配置项「聊天生成 → 最近图片数量」（`natural_language.recent_images`）默认 20，范围 0～20，填零会关闭并清空原有记录。「图片保留时间（秒）」（`image_ttl_seconds`）默认 86400，按最近使用时间保留最多 24 小时，独立于临时素材上下文。已有配置显式保存的数量仍保留，升级时请调为 20。原图和约 50 字简介保存在插件运行目录的 `image_memory/`；按用户与会话隔离，相同内容去重，最近使用的排在前面。访问和定期清理会删除过期记录及无引用文件；最多保留 128 组用户会话。

记录包含实际观察或使用过的参考图和已经发出的生成图片；生成结果优先淘汰，不挤掉参考图，排队任务与待补需求使用的图片优先保留，仍受总数量和时间上限约束。重复观察只读取已保存的简介，不重复获取原消息、下载或识图；真正绑定到工作流时读取保存的原始字节。稳定图片 ID 可脱离 `context_id` 使用。首次获得简介会调用一次所选视觉模型；同一图片并发观察共用请求。摘要失败仍保存原图，后续提示依据对话或询问用户；视频和语音不加入这份记录。

工作流查询应只返回概要，指定名称才展开一个工作流的参数；素材查询不附带工作流字段。关闭聊天历史读取能力后，工作流查询和 `rh_media(source="memory")` 应仍能使用。模拟上下文过期或插件重启，再通过稳定图片 ID 观察和绑定，确认没有重新获取消息、下载或识图。另需验证超过 24 小时的图片不可读取，连续生成结果不会挤掉缓存中的参考图。

部署后可用两张内容明显不同的图片验证：分别观察或生成后，发新消息要求使用其中一张；检查模型根据简介选择、原图上传正确，重载插件后仍可使用。将数量改为 1 应只保留一张符合优先级的图片，改为 0 后旧记录不再出现。此功能的离线测试还覆盖磁盘故障不阻断成品发送。

离线测试已覆盖模型下拉数据、视觉默认项、新节点必填开关、删除节点保存，以及旧英文配置保存再重载；未在真实宿主页面中点击验证。节点表单的数字边界用空字符串表示未设置，不写入空对象。旧 `detect`、`llm`、`cleanup` 分组会在 SDK 补默认值前迁移，保留原有的关闭开关、模型和零值；显式配置的新 `feature` 值优先。

- `queued`：已持久化预约，正在等待或准备输入。提交时平台返回并发或限流已满（415/421/1003/1011/1520）说明任务没有创建，会回到排队，30～120 秒后重新提交。
- `submitting`：已开始付费提交；进程在此阶段退出，会转为 `unknown_submission`。
- `unknown_submission`：可能已创建远端任务，保留额度及并发名额，禁止自动重提。管理员在 RunningHub 后台核对后，发送 `/rh核对 本地任务ID 远端任务ID` 关联已有任务。只有确认没有创建时才使用 `/rh核对 本地任务ID 未创建` 释放名额。
- `pending` / `tracking_paused`：已有远端编号；查询短暂失败或超时后继续后台跟踪，不表示远端生成失败。
- `needs_attention`：查询被服务端明确拒绝（如 Key 失效）。暂停自动查询，但保留远端编号、活动记录与远端并发名额。修复配置后用 `/rh状态` 恢复查询；确认不再需要时，管理员用 `/rh核对 本地任务ID 放弃` 结束跟踪并释放名额。命令的小时额度、工具的 Bot 每日额度仍按原提交时间计算。平台返回任务不存在（423/807/1004）时直接记为失败。
- `success`：生成完成。`delivery_status` 另行记录 `pending`、`partial`、`failed`、`uncertain`、`sent`。
- `uncertain`：发送可能已经成功，自动重复发送可能造成重复消息。先查看聊天结果，再决定是否 `/rh补发`。进程退出前正在发送的项也按此处理。

`/rh状态 [任务ID]` 可查看最近任务并恢复未完成任务的后台处理。取消、状态和补发不受生成次数上限影响，仍限制为当前会话自己的任务，管理员可管理当前会话其他用户的任务。远端取消响应不确定或被明确拒绝时都继续跟踪，由查询结果决定最终状态。

草稿、普通素材候选和临时视觉摘要有 TTL 及数量上限；插件重启后需要重新查询上下文。最近图片的原图和简介、已排队请求及生成记录会持久化。未保留的参考文件过期且无法刷新时需要用户重发；插件不会用另一张图代替。

日志不可写或 JSON 损坏时拒绝创建新任务。不要删除活动任务日志来解除报错，应先备份和核对远端状态。
