# RunningHub 通用工作流插件

通过配置适配 [RunningHub](https://www.runninghub.ai)（国外）/ [RunningHub 国内](https://www.runninghub.cn) 的大部分工作流，无需修改代码即可跑文生图、图生视频、参考图/音频/视频工作流等。

## 功能特性

- 可配置多个工作流（工作流 ID、设备类型、区域）
- 每个工作流可自由增删输入节点（节点 ID / 字段名 / 默认值 / 节点类型）
- 节点类型：主提示词 / 可编辑配置 / 固定默认值 / 图片 / 音频 / 视频
- 文字节点支持 LLM 扩写（可配置模板文件路径）
- 文件节点（图/音/视频）交互式收集，可只传部分，发「跳过剩余」直接开始
- `/识别工作流` 自动识别并写入配置，自动判断国内/国外区域
- 命令、LLM 工具、公开 API 三种触发方式
- 发送后自动撤回（仅 NapCat 适配器生效）

## 安装

```bash
cd <MaiBot目录>/plugins
git clone https://github.com/achenjins/runninghub-workflow-adapter.git runninghub-workflow-adapter
pip install -r runninghub-workflow-adapter/requirements.txt
```

重启 MaiBot（或 WebUI 热重载）即自动加载。

## 快速上手

1. **填 API Key**：在 WebUI 插件配置页填 `server.api_key`（国外）或 `server.api_key_cn`（国内），至少填一个。
2. **识别工作流**：国内工作流发 `/识别国内工作流 <工作流ID> <名称>`，国外工作流发 `/识别国外工作流 <工作流ID> <名称>`，插件自动识别输入节点并写入配置。
3. **运行**：`/跑图 <工作流名> <描述文本>`，按提示上传参考文件、确认配置，等待结果自动发回。

## 配置项说明

### [server] RunningHub 服务

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `base_url` | `https://www.runninghub.ai` | 国外平台基地址（不可修改） |
| `api_key` | 空 | 国外 API Key（与国内至少填一个） |
| `base_url_cn` | `https://www.runninghub.cn` | 国内平台基地址（不可修改） |
| `api_key_cn` | 空 | 国内 API Key |

- 国外走 `runninghub.ai`，国内走 `runninghub.cn`；两者可只填一个。
- 识别国内/国外工作流分别用对应区域的 key 拉取；对应 key 未填会提示检查配置。

### [generation] 生成参数

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `poll_interval` | 15 | 任务轮询间隔（秒），最小 3 |
| `max_wait` | 1800 | 任务最大等待时间（秒），最小 60 |
| `max_concurrent` | 2 | 同时进行中的任务数上限（1–10） |
| `download_timeout` | 120 | 下载结果超时（秒），最小 30 |

### [cleanup] 自动撤回

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `enable` | false | 启用发送后自动撤回（仅 NapCat 适配器生效） |
| `recall_seconds` | 90 | 发送后自动撤回的秒数（0 表示不撤回） |

### [detect] 节点识别

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `use_llm` | true | 用内置 LLM 识别节点（仅 `/详细识别工作流` 使用），失败自动回退启发式 |
| `model` | utils | 识别用的模型槽位：`utils` 快 / `replyer` 强 / `planner` 快 |

### [llm] 提示词扩写

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `enhance_model` | utils | 扩写用的模型任务槽位 |

### [access] 访问控制

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `allow_users` | [] | 允许使用的用户 ID 白名单；留空表示不限制 |
| `allow_groups` | [] | 允许使用的群组 ID 白名单；留空表示不限制（私聊不受群组白名单约束） |
| `max_per_user_per_hour` | 0 | 每用户每小时任务上限；0 表示不限制 |

> 默认全部放行，与旧版行为一致；配置白名单或频率上限后才生效。

### [workflows] 工作流列表

每个工作流一项（WebUI 中可自由增删）：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `name` | 空 | 工作流显示名称，命令调用用（如 `/跑图 动漫生图 ...`） |
| `workflow_id` | 空 | RunningHub 工作流 ID |
| `instance_type` | Standard | 设备类型：`Standard` / `Plus` |
| `region` | overseas | 区域：`overseas` 国外 / `domestic` 国内，决定用哪个 API |
| `llm_enhance` | false | 是否先按模板扩写命令文本再传入提示词节点 |
| `llm_template_path` | 空 | 扩写模板文件路径（相对插件目录，如 `templates/my_template.txt`） |
| `input_nodes` | [] | 输入节点列表 |

### 输入节点字段

| 字段 | 说明 |
|------|------|
| `node_id` | RunningHub 工作流中的节点 ID |
| `field_name` | 节点字段名（如 prompt / text / image / audio） |
| `field_value` | 输入内容；作为默认值使用 |
| `value_type` | 节点类型（见下表） |
| `label` | 该输入的中文说明 |

### 节点类型（value_type）

| 类型 | 含义 | 行为 |
|------|------|------|
| `prompt` | 主提示词 | 接收命令/LLM 扩写文本，**整个工作流仅一个**，多了运行时报错 |
| `text` | 可编辑配置 | 带默认值，运行时固定询问用户是否修改 |
| `default` | 固定默认值 | 直接使用，不询问；无默认值时跳过 |
| `image` | 参考图 | 留空则等待上传 |
| `audio` | 参考音频 | 留空则等待上传 |
| `video` | 参考视频 | 留空则等待上传 |
| 空 | 自动推断 | 按字段名推断（image→图片、audio→音频、video→视频、其余→文字） |

> 单个工作流最多 32 个节点。

## 命令

| 命令 | 说明 |
|------|------|
| `/跑图 <工作流名> <描述文本>` | 运行配置好的工作流 |
| `/工作流` | 列出已配置的工作流 |
| `/识别国内工作流 <工作流ID> [名称]` | 识别国内工作流（region=domestic），仅提取文字/图片/音频/视频/分辨率/长宽比例 |
| `/识别国外工作流 <工作流ID> [名称]` | 识别国外工作流（region=overseas），仅提取文字/图片/音频/视频/分辨率/长宽比例 |
| `/详细识别国内工作流 <工作流ID> [名称]` | LLM 详细识别国内工作流全部节点（步数/采样器/CFG/种子等） |
| `/详细识别国外工作流 <工作流ID> [名称]` | LLM 详细识别国外工作流全部节点（步数/采样器/CFG/种子等） |

> 简化识别与详细识别都会调用 LLM，只是提示词不同（简化只用关键节点提示词，详细用全量提示词），LLM 失败时自动回退启发式规则。

## 执行流程

`/跑图` 的完整流程：

1. **解析**：按工作流名找到配置，校验主提示词节点数量、区域 API Key。
2. **扩写**（可选）：若开启 `llm_enhance`，用模板把命令描述扩写为提示词（延后到文件收集完成后执行，以便把实际上传的文件数量告知扩写 LLM）。
3. **文件收集**：若存在图片/音频/视频节点，提示「请上传：图片 N 张、音频 M 段…」，用户可一条消息发多个、**可只传部分**；发「跳过剩余」直接进入下一步。文件按类型自动分配到对应节点。
4. **配置确认**：若存在 `text`（可编辑配置）节点，固定询问「可修改：1.宽度=512 …」，用户回复新值（如「512 16:9」，`-` 保持默认，「不变」全默认）。
5. **提交**：调用对应区域的 API 提交任务。
6. **轮询发送**：后台轮询任务状态，完成后结果自动发回（图片直接发图，视频等发下载链接），按配置可自动撤回。

识别命令（国内/国外、简化/详细）流程：用对应区域的 key 拉取工作流 → LLM 识别节点（失败回退启发式）→ 写入配置（区域已设定）→ 回复「识别成功」。

## 工具与 API

- **LLM 工具**：`run_workflow(workflow_name, prompt, stream_id)`。若工作流需要参考文件，返回 `waiting=true` 与 `required_files`，模型把文件要求转告用户即可，插件自动接收文件继续。
- **公开 API**：`ctx.api.call("rh-workflow-adapter.run_workflow", workflow_name=..., prompt=..., stream_id=...)`

## 常见问题

- **识别结果为空**：`/识别工作流` 只识别关键节点，某些自定义节点识别不到，可改用 `/详细识别工作流` 或手动在 WebUI 加节点。
- **运行时报「对应 API Key 未填写」**：该工作流的 `region` 对应 key 没填，检查 `[server]` 配置或调整工作流 `region`。
- **文件上传后无反应**：确认插件已重载（新版本把消息拦截从 ON_MESSAGE 事件改为 Hook 通道），查看日志 `[识别]`/`已接收输入`/`任务已提交`。
- **扩写不生效**：确认工作流 `llm_enhance` 已开、`llm_template_path` 指向存在的文件；日志搜「扩写」定位（模板为空 / LLM 失败）。
